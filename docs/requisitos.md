# Requisitos (ISO/IEC/IEEE 29148)

| ID | Petición literal del PO | Criterio (Dado / Cuando / Entonces) | Estado |
|---|---|---|---|
| REQ-001 | "Ninguna página pública lanza excepciones en el cliente." (INC-001, 3 nov 2026) | Dado cualquier página pública con datos reales, cuando se abre en un navegador a 390 o 1366 px, entonces no hay excepciones no atrapadas, ni errores de hidratación (#418/#423/#425), ni la pantalla "Application error". | CUMPLIDO |
| REQ-002 | "Si una sección falla, el resto de la página sigue funcionando." | Dado que una sección (viajes en /tours, carrusel del home) lanza un error en el navegador, cuando se renderiza, entonces esa sección se oculta, se registra en consola y el resto de la página sigue visible. | CUMPLIDO |
| REQ-003 | "Ningún deploy llega a producción si el smoke test falla." | Dado un merge a main, cuando el workflow publica, entonces primero sube una versión sin tráfico, le corre la prueba de humo y solo si pasa le da el 100%; después vuelve a probar producción y, si falla, regresa a la versión anterior. En cada PR corre la misma prueba sobre una versión sin tráfico. | CUMPLIDO (verificado en el deploy de #60: humo antes y después, verde) |
| REQ-004 | Causa raíz de INC-001: las tarjetas de viajes traducían el país en el navegador. | Dado un viaje en Hong Kong (u otro país), cuando el servidor y el navegador tienen datos de idioma distintos, entonces la tarjeta muestra el nombre calculado en el servidor y el HTML es idéntico en ambos. | CUMPLIDO |
| REQ-005 | "Ficha del tour" + "Franja + ventana al reservar" (3 nov 2026) — franja | Dado un tour de una ciudad con transporte publicado, cuando abro su ficha, entonces bajo el botón de apartar veo una franja con ese transporte (si no hay en la ciudad, el del mismo país; si no hay, nada). | CUMPLIDO (producción, PR #61, 3 nov 2026) |
| REQ-006 | Ventana al reservar | Dado que hay transporte para el lugar del tour, cuando toco "Apartar con un asesor", entonces aparece "Completa tu viaje" con 1–3 opciones y "No, gracias"; si acepto, el WhatsApp incluye el transporte; si no, sale el mensaje normal; no vuelve a salir en esa visita. | CUMPLIDO (producción, PR #61, 3 nov 2026) |
| REQ-007 | "y viceversa" (gate de venta cruzada) | Dado un transporte publicado, cuando abro su ficha, entonces veo una franja "Tours en {ciudad}" con tours de esa ciudad (o país). | CUMPLIDO (producción, PR #61, 3 nov 2026) |
| REQ-008 | Reglas de INC-001 para la venta cruzada | Los bloques respetan TRANSPORT_ENABLED, van en SectionBoundary y sus textos/precios llegan calculados del servidor (6 idiomas). | CUMPLIDO (producción, PR #61, 3 nov 2026) |
| REQ-009 | "asegura que quede cuando estén reservas en línea" (3 nov 2026) | Dado BOOKINGS_ENABLED encendido (reserva con calendario), cuando abro la ficha de un tour con transporte en su ciudad, entonces la franja aparece bajo el calendario (una sola vez). La ventana al reservar en línea va en la ola X2b (confirmación/pago). | CUMPLIDO (producción, PR #61, 3 nov 2026) |
| REQ-010 | Gate A/C — precio correcto de tours de pago | Dado un evento de pago, cuando se calcula el precio, entonces se usa la tabla por número de adultos, se cobra hoy `payableNowPricePerGroup`, no se aceptan niños y nunca se toma el precio del navegador. | CUMPLIDO (tests) |
| REQ-011 | Gate A — checkout de Freetour | Dado el piloto encendido y la política confirmada, cuando reservo un tour de pago, entonces se crea la reserva, se pide el checkout con URLs https de regreso y el navegador va a pagar. | CUMPLIDO (tests; apagado en producción) |
| REQ-012 | Verificar el pago antes de confirmar | Dado que regreso del checkout, cuando el pago está confirmado (status 1 o error 61) se marca pagada y se manda UNA confirmación; si sigue pendiente (63) se reintenta cada ≥10 min hasta que venza; 38/39 = cancelada. | CUMPLIDO (tests; apagado en producción) |
| REQ-013 | Gate B — política que confirme Freetour | Dado que Freetour no ha confirmado por escrito el texto de reembolso, cuando se muestra un tour de pago, entonces no se afirma nada sobre reembolsos y no se puede pagar. | CUMPLIDO (tests) |
| REQ-014 | Gate C — piloto y luego MXN | Dado PAID_TOURS_ENABLED, cuando se recomiendan tours (home, mapa, correos), entonces NO entran tours de pago salvo PAID_TOURS_IN_RECOMMENDATIONS; el aviso dice que el cargo es en euros. | CUMPLIDO (tests) |
